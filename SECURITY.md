# Security

terminumd gives a browser page your terminals (a shell as you) and your files, so it is built
to be reachable only by its own page. The specs hold the cases (`docs/specs/terminum.md`
AC-09, AC-10, §9 Security; `terminum-files.md` §9 Security; `terminum-remote.md` §9 Security).

| Threat | Defense |
|---|---|
| Other machines | terminumd listens on `127.0.0.1` only; other devices reach it through `tailscale serve` (HTTPS on your tailnet), which runs on this Mac; `tailscale funnel` (the public internet) is refused with 403 |
| Web pages in any browser (CSRF, DNS rebinding) | every request that reads or changes terminals or files needs a sign-in: the header `X-TM-Session` (an `<img>` may carry it as `?t=` on a GET; the WebSocket as its subprotocol); the `Host` is `127.0.0.1:<port>` exactly, a `*.ts.net` name or one of `allow_hosts` in `web.json`; writes need `Content-Type: application/json` and the exact `Origin` (`http://` for the loopback address, `https://` for a tailnet name; only the Mac's own, unforwarded requests may leave it out); WebSockets and uploads need the exact `Origin`; no CORS headers; `/internal/*` answers 404 over TCP |
| Why not a cookie on loopback | a cookie for `127.0.0.1` reaches every local port, so any other local web server you open would receive it; the sign-in stays in the page's own origin's storage and is sent as a header |
| Getting a sign-in | the password, set only by the `terminum` command over the Unix socket `~/.terminum/state/terminumd.sock` (0600 in a 0700 folder); until it is set no browser signs in. The right password (`POST /auth/login`) gets a 256-bit sign-in in the answer's body (never in an address, never a cookie), which the page keeps in its origin's storage; terminumd keeps only its SHA-256 (`signins.json`, 0600, 30 days, at most 20). Sign out ends that browser's; `terminum signout` and a new password end every one and close every page. The sign-ins of 0.5.0 and before (`local-sessions.json`, `web-sessions.json`) are removed at start: their secrets stay in the storage of an origin any program may serve now |
| Guessing the password | the password opens your terminals and files, and adds and removes hosts and attached sessions; kept only as salted PBKDF2-SHA256 (200,000 iterations) in `web.json` (0600); checked one at a time, 1 s per wrong try; after 5 from one address it waits 15 s doubling to 5 min, after 20 from all addresses every address waits, counted apart for this Mac's own requests and forwarded ones (guesses from the tailnet never hold the Mac's browser); the address behind `tailscale serve` is the last `X-Forwarded-For` entry, believed only from loopback (a program on this Mac can name any address, so for it only the count of all holds); `terminum password` and `terminum signout` start the brakes over, so guesses from elsewhere never keep you out for long. Any program on this Mac can try passwords on loopback too: with the one-time codes of 0.5.0 a sign-in also proved that its user sat at the Mac; now the password alone does |
| A program on terminumd's port (terminumd not running: a login, an upgrade, a crash) | launchd holds `127.0.0.1:<port>` from the moment the agent is loaded (socket activation) and hands it to each terminumd it starts, so while terminumd is down, restarting or upgraded no other program can bind it; `terminum status` reports a port another program held when the agent was loaded (`terminum restart` takes it back). A page that is already loaded and reconnects asks `/api/hello` with a fresh nonce and the sign-in's id before it sends its secret; only a terminumd that issued that sign-in holds its proof key (an HMAC of the secret) and can answer HMAC-SHA256(proof key, nonce). Left: before the agent is loaded (or after an uninstall, or when the port was taken at load; on Linux and with `TM_NO_LAUNCHD`, where terminumd binds the port itself, while it is down) another program can serve a page on the port; that page runs its own script in the page's origin, can read the sign-in stored there and can ask for the password, and `tailscale serve` forwards to it as well, so do not open the page then |
| Local processes of other users | everything under `~/.terminum` is private (folders 0700, files 0600); the CLI talks to terminumd only through the Unix socket, never over TCP |
| The page itself (terminal output, a malicious README or SVG) | CSP `script-src 'self'` with no eval, `frame-ancestors 'self'`; terminal output is text: it reaches only the panel's Markdown rules (raw HTML off, `http(s)`, `mailto` and relative links, no remote image) and Mermaid in strict mode without HTML labels, drawn as an `<img>`; a diagram guessed from unfenced text is drawn only on the user's press; links never navigate the page; SVG only through `<img>`; HTML files in a sandboxed frame without scripts; only regular files are read |
| Typing into tmux | user text reaches tmux only as one quoted argument (`'…'` with `'\''`), `#` doubled where tmux expands formats (`-c`, `-n`, `rename-window`, `select-pane -T`), so a folder named `#(cmd)` runs nothing; control characters are never put on tmux's command line: keys go by tmux's names, a paste through a tmux buffer from a 0600 file; `send-keys -H` only for mouse reports and CSI u keys terminumd builds itself; a paste holding control characters is refused |
| Typing into the wrong terminal | the Files panel's "insert path" and "cd" name the pane they act on, `cd` goes only into an idle shell, nothing sends Enter; names are quoted for the pane's own shell or refused (control, bidi and zero-width characters) |
| Writes outside your files | the Files API writes only under `TM_WRITABLE_ROOTS` (`$HOME:/tmp`), judged on resolved paths (a symlink is judged where it lives for rename and Trash); delete moves to the Trash |
| Remote hosts | a host is the ssh string you gave (`settings.json`), checked against an allowlist: options `-p -l -i -J -4 -6 -C` only (no `-o`, no `-F`: a config file or an option can hold ProxyCommand), a destination not starting with `-`, `--` before it, no command but terminumd's own; `BatchMode=yes` (no prompts); the files agent is copied to a host only after you enable it, takes its token on stdin, listens on a Unix socket in a private folder, writes only under that user's `$HOME` and `/tmp`, exits when its ssh ends; its answers are capped (64 MB) and timed (30 s idle, 120 s total); Finder actions are refused for remote files |
| Your own tmux server | terminumd attaches only the sessions you named (`attach` in `settings.json`, "Attach tmux sessions"), as a control client of the server on that socket (`$TMUX_TMPDIR`, else `/tmp`, `/tmux-<uid>/<socket>`, which tmux keeps 0700 to you); it never starts that server, never makes or closes a session there, and a socket name is letters, digits, `-`, `_`, `.` only; terminum's own socket is refused there. Your `~/.tmux.conf` hooks and plugins see its clients. On a host (`hosts.<name>.attach`) the same holds for the tmux its `terminum` session is on: the other sessions there are counted and named to the page only to offer them, never typed into or sized until you attach one; each is attached over its own ssh connection by session id (`$N`, so no name reaches the host's shell), with `-E` (terminumd's ssh environment is not copied into it). Whoever signs in, also from another device, can type into every attached session |
| Quick shell | a tmux window like any other, made in the shown pane's folder (checked as for New window) and shown by the page itself in a same-origin frame (`frame-ancestors 'self'`) |
| Other devices | they come through `tailscale serve`: HTTPS with Tailscale's certificate up to this Mac, then plain HTTP on loopback, which never leaves it. A forwarded request (any `Forwarded`, `X-Forwarded-*` or `Tailscale-*` header: `tailscale serve` always adds `X-Forwarded-Host` and passes the browser's `Host` through as it came) cannot use Finder or the default app, type a path into a terminal (403 `not_here`) or choose about updates. A signed-in device has a shell anyway: this guards against accidents, it is not a boundary. On iOS, Safari may drop a page's storage after 7 days without a visit; the page then asks for the password again |
| Bookmarks and traces | bookmarks hold selected terminal text and your note in `web-bookmarks.json` (0600), sent only over a signed-in socket and shown as text; terminumd stamps their pane, title and host. `?trace=1` records no typed text, screen content, title or host name, for at most 15 minutes or 20 MB, in `~/.terminum/logs` (0600); `?trace=2` stays in the page |
| Reboot restore | `layout.json` (0600) holds sessions, windows, layouts, folders and a pane's kind; never output, history, environment or a command line other than a checked ssh recipe; only shells are started again |
| The update check | the only request terminumd makes by itself: one `HEAD` to the project's GitHub releases page a day; only a tag `vMAJOR.MINOR.PATCH` is kept and shown as text; nothing is downloaded or installed; `state/no-update-check` turns it off |
| The installer and releases | `install.sh` and `terminum upgrade` verify the signature of `SHA256SUMS` with the release key they carry before the checksum, refuse root; releases are built and signed only on the maintainer's Mac from a clean `main` with locked dependencies (`docs/RELEASING.md`) |

Report a vulnerability privately through the repository's security advisories ("Report a
vulnerability"), not in a public issue. Include the version (`terminumd --version`), the
macOS and tmux versions, and the smallest reproduction.
