# Security

terminumd gives a browser page your terminals (a shell as you) and your files, so it is built
to be reachable only by its own page. This is the threat model: what is at stake, who can reach
it, what stops them and what is left. The exact checks are in the specs (`docs/specs/terminum.md`
AC-09, AC-10; §9 Security of each spec).

| Threat | Defense |
|---|---|
| Other machines | terminumd listens on `127.0.0.1` only; other devices reach it through `tailscale serve` (HTTPS on your tailnet), which runs on this Mac; `tailscale funnel` (the public internet) is refused (AC-10) |
| Web pages in any browser (CSRF, DNS rebinding) | every request that reads or changes terminals or files needs a sign-in, sent as a header and never in an address (a copied image address signs nothing in); the `Host` must be a name terminum serves; writes need a JSON `Content-Type` and the page's exact `Origin`; WebSockets and uploads always need the exact `Origin`; no CORS headers; `/internal/*` answers 404 over TCP. The exact checks: AC-09, AC-10, `terminum.md` §9 Security |
| Other local web servers | a cookie for `127.0.0.1` reaches every local port, so any other local web server you open would receive it; the sign-in is never a cookie: it stays in the page's own origin's storage and is sent as a header (AC-09) |
| Getting a sign-in | the password, set only by the `terminum` command over its Unix socket (0600 in a 0700 folder); until it is set no browser signs in. The right password gets a sign-in, of which terminumd keeps only a hash and a proof key (AC-09). Sign out ends that browser's; `terminum signout` and a new password end every one and close every page. The sign-in files of old installs are removed at start (AC-09) |
| Guessing the password | the password opens your terminals and files, and adds and removes hosts and attached sessions. It is kept only as a salted, slow hash (0600); wrong ones are braked per address and for all, counted apart for this Mac's own requests and forwarded ones (how, the numbers and what starts them over: AC-09). Any program on this Mac can try passwords on loopback too, and can name any address with a forwarded `Host`, so for it only the count of all holds; a sign-in proves the password alone, never that its user sits at the Mac |
| A program on terminumd's port (terminumd not running: a login, an upgrade, a crash) | launchd holds the port from the moment the agent is loaded, also while terminumd is down, restarting or upgraded, so no other program can bind it (`terminum-lifecycle.md` AC-08); `terminum status` reports a port another program held when the agent was loaded (`terminum restart` takes it back). A page that is already loaded and reconnects proves the server first: only a terminumd that issued that sign-in holds its proof key. The secret never goes out after the sign-in: requests carry a credential of that terminumd's boot, so a request that reached another program before the page noticed gave it nothing the next terminumd accepts (AC-09). terminumd refuses the secret itself from a browser that sends Sec-Fetch-Site: a tripwire for a page that would send it, not a barrier (which browsers: AC-09). Reading `signins.json` (0600) gives the proof keys, which make such credentials: whoever can read it is this user, who can read the browser's storage too. Left: before the agent is loaded (or after an uninstall, or when the port was taken at load; on Linux and with `TM_NO_LAUNCHD`, where terminumd binds the port itself, while it is down) another program can serve a page on the port; that page runs its own script in the page's origin, can read the sign-in stored there (the per-boot credentials do not help here) and can ask for the password, and `tailscale serve` forwards to it as well, so do not open the page then |
| Local processes of other users | everything under `~/.terminum` is private (folders 0700, files 0600); the CLI talks to terminumd only through the Unix socket, never over TCP (AC-09) |
| The page itself (terminal output, a malicious README or SVG) | CSP `script-src 'self'` with no eval; every answer, refusals too, carries the hardening headers (AC-09); `/custom.css` only with the sign-in; terminal output is text: it reaches only the panel's Markdown rules and Mermaid in strict mode, and a diagram guessed from unfenced text is drawn only on the user's press (`terminum-terminal.md` §9 Security); links never navigate the page; SVG only through an image, HTML files in a sandboxed frame without scripts, only regular files are read (`terminum-files.md` §9 Security) |
| Typing into tmux | user text reaches tmux only as one quoted argument, `#` doubled where tmux expands formats, so a folder named `#(cmd)` runs nothing (`terminum.md` §9); control characters are never put on tmux's command line: keys go by tmux's names, a paste through a tmux buffer, on this Mac from a 0600 file; `send-keys -H` only for mouse reports and CSI u keys terminumd builds itself; a paste holding control characters other than tab and line ends is refused |
| Typing into the wrong terminal | the Files panel's "insert path" and "cd" name the pane they act on, `cd` goes only into an idle shell, nothing sends Enter; names are quoted for the pane's own shell or refused (control, bidi and zero-width characters) (`terminum-files.md` AC-60) |
| Writes outside your files | the Files API writes only under `TM_WRITABLE_ROOTS`, judged on resolved paths; delete moves to the Trash (`terminum-files.md` §9 Security) |
| Remote hosts | a host is the ssh string you gave, checked against an allowlist, so no option or config file can hold a ProxyCommand and no command runs but terminumd's own, without prompts; the files agent is copied to a host only after you enable it, takes its token on stdin, listens on a Unix socket in a private folder, writes only under that user's `$HOME` and `/tmp`, exits when its ssh ends; its answers are untrusted, capped and timed; Finder actions are refused for remote files. An agent on a host reaches its project's tasks through the host's link: a broken host can read them and write comments its project's other agents read, which they are told are data (`terminum-kanban.md` AC-120). The only processes terminumd ends on a host are the user's orphaned tmux control clients that are terminum's; never the tmux server, another user's process or a client whose parent lives. Accepted risks: one with `ignore-size` that init itself runs on purpose (a system unit) would be taken for one, and where tmux rewrote the command line so would another control client of that server left orphaned. The exact rules: `terminum-remote.md` AC-81, AC-82, §9 Security, which also has the agents' link to a host (AC-99) |
| Your own tmux server | terminumd attaches only the sessions you named, as a control client of the server on that socket (`$TMUX_TMPDIR`, else `/tmp`, `/tmux-<uid>/<socket>`, which tmux keeps 0700 to you); it never starts that server, never makes or closes a session there, and a socket name is letters, digits, `-`, `_`, `.` only; terminum's own socket is refused there. Your `~/.tmux.conf` hooks and plugins see its clients. On a host the same holds for the tmux its `terminum` session is on: the other sessions there are counted and named to the page only to offer them, never typed into or sized until you attach one (AC-89). Whoever signs in, also from another device, can type into every attached session |
| Quick shell | a tmux window like any other, made in the shown pane's folder (checked as for New window) and shown by the page itself in a same-origin frame (`frame-ancestors 'self'`) |
| Other devices | they come through `tailscale serve`: HTTPS with Tailscale's certificate up to this Mac, then plain HTTP on loopback, which never leaves it. A forwarded request cannot use Finder or the default app, read the paths of a drop from macOS's drag pasteboard, type a path into a terminal or choose about updates (AC-10; `terminum-terminal.md` AC-36). A signed-in device has a shell anyway: this guards against accidents, it is not a boundary. On iOS, Safari may drop a page's storage after 7 days without a visit; the page then asks for the password again |
| Coding agents' hooks | `terminum hooks install` writes only terminum's Claude Code plugin folder (terminum never edits Claude Code's settings) and terminum's entries in Codex's `hooks.json` and block in its `config.toml`, backed up first; Codex runs the hooks only once you trust them in `/hooks`. The hook sends a few fields of each event, never a tool's output, a file's text or the agent's answer (`terminum-agents.md` AC-39), only to terminumd's socket, or on a host to a Mac's link (`terminum-remote.md` AC-99); any process of yours can post there, and a made-up event can change a listed pane's shown state, its tool and wait texts and add a sent entry show three integers and shape-checked subagent IDs on a task's card and, for a session Dispatcher started, move its task as that event would; none of its words runs or reaches tmux, and only a session ID of a shape that is no flag and no shell word reaches a command line (the row on Dispatcher) |
| Plans and tasks of coding agents | an agent's plan and what it writes on tasks are model-written text: kept 0600, control characters and what hides what a line reads (bidi controls, zero-width characters, the soft hyphen, word joiners, line separators and tag characters) dropped before they are redacted as sent history is, limited in length and number (`terminum-agents.md` AC-97, `terminum-kanban.md` AC-115); sent only to signed-in pages; plan text shown as plain text, a task's text and comments as Markdown with raw HTML off. The agent of a session does all on its own tasks, reads and comments on its project's others: a scope, no boundary, since `terminum mcp` names the pane from the agent's environment (`TMUX_PANE`) and a process of the same user can name another, as it can read the store. What tools answer of a task is said to be data, never instructions. `terminum mcp` starts in every Claude Code and Codex session on the Mac, but outside a terminum pane it offers no tools and no instructions; it listens on no port: it speaks MCP over the agent's stdin and stdout and only forwards each call to terminumd's private socket, or on a host a Mac's link; its tools write only terminumd's plan and the store, never tmux or the pane, and read a file only inside the session's folder, on resolved paths; terminumd's stale-plan reminder and the line telling a session of a human's move are fixed words with numbers, a column and a user name, given back through the hook's answer, never typed |
| The tasks' store | one SQLite file, `kanban.sqlite`, and files in `attachments/`, 0600 in 0700, on the Mac alone: an Agent never opens one. Reached only with the sign-in; a file's bytes only with its header, never by an address. A file shows inline only as a raster picture checked by its bytes; SVG, HTML and all else download, nothing runs on the page's origin. A human can purge a file or a text for good, for a secret pasted by mistake; agents' text is redacted, a human's is not. A corrupt or unreadable store is set aside, never written over (`terminum-kanban.md` AC-109, AC-119). Its input log holds what was typed into panes: a password at a recognized prompt, under sudo and the like, or a line begun with a space is not kept, a password typed at a prompt it does not recognize is (`terminum.md` AC-147) |
| Dispatcher's typing and closing | it types only in a pane it started and marked (`@terminum-run`, read back just before), only through the typing gate of `terminum-dispatcher.md` §9 (several tasks run together go by their numbers and your message alone, each text shown to you first; in one session an agent-written task can still sway the others once read): the screen must read as an empty box of that agent, an unknown screen is not empty, a human's keys through the page wait behind it (a tmux client you attach yourself does not); only task IDs with fixed words or the prompt of a human's RUN, whose window shows it first. It closes only such a pane, its agent idle. It reads the mark and the recorded exit in the very tmux command that pastes, and drops what the tty holds when an agent ends, so a task's words never reach the shell it leaves. A hook's fields are data: only a shape-checked session ID reaches a shell. A task's text reaches an agent as a prompt only by a human's RUN. Its `ps` reads no arguments. `terminum hook` sums a turn's tokens beside its transcript, on its own machine: three integers leave it, no path and no text. At a task's time budget it signals what runs under the pane it started, by pid and start time read just before, its shell spared; never by name or pattern |
| Idle agents' exit | off until you set its days in Settings; then terminumd types only Ctrl+C twice and `/exit` with Enter, fixed words of its own, into a pane whose Claude Code or Codex is idle, its box shown empty (no draft, no question: a permission is never answered), the same program in front, a bare shell's pane no page and no tmux client of yours showed for those days, not Dispatcher's; every key is read against the pane again just before it and logged (`terminum-agents.md` AC-153). What the agent ran in the background ends with it |
| The pool of agents | an agent's command (`terminum-dispatcher.md` AC-137) is what you wrote, run in your login shell as if you typed it, and kept and shown as written: keep a secret in your shell's environment, never in the command. The board is the only way terminum offers to write one, and anyone signed in on the page can, which is no more than typing in a terminal there; `terminum mcp` has no tool for them. That is a scope, no boundary: a process of yours can change the store or the password, as it can edit your shell's start files, so RUN's dialog shows the command in full before it runs. It is one line with no control or invisible characters |
| Codex's trust of terminum's hooks | Codex trusts a hook entry by the hash of the entry in `hooks.json`, not of the `terminum` program it names: an upgrade of terminum changes what the hook does without a new trust prompt (terminum keeps its entries byte for byte so a trusted entry stays trusted). Its MCP tools in `config.toml` are approved without a prompt; install and remove change only the lines terminum wrote, and refuse a `[mcp_servers.terminum]` table of yours or a file that changed while they ran (`terminum-agents.md` AC-97) |
| Sent history | what you send (commands at a shell prompt, prompts to an agent) is kept on the Mac (0600, folders 0700), sent only to signed-in pages; a line starting with a space is never kept; values of words named like secrets and words of secrets' shapes are written as `[redacted]`, a quoted value is hidden whole, but a quote that opens inside a value's word (`TOKEN=abc'd e'`) is not followed; other secrets typed on a command line are kept as typed (`terminum-terminal.md` AC-90) |
| A program's clipboard writes (OSC 52) | terminumd reads a clipboard write from a pane's output (terminum's own tmux keeps `set-clipboard off`, so nothing reaches the Mac's clipboard that way there; a host's or your own server's setting is theirs) and hands it to a page only just after that page's left mouse release to that full-screen pane; the page shows it only as Copy, [+] and Ask, never put on the clipboard or typed until you press one; what could send keys or make a pasted line read otherwise than it runs is taken out, and terminal text leaving the page is cleaned the same way; a read is never answered (AC-06; `terminum-terminal.md` AC-37). Left: a program that writes the clipboard on its own over and over (a loop, a hostile file shown in a pager with the mouse) can have its text offered, or put in place of what the program copied, after one of your releases, whatever you dragged over and whatever is on the screen; Copy's tooltip (none on a phone) and its toast say only its line count and first line, and it puts the text on the clipboard without showing it whole, so check what you paste (Ask and [+] show it whole) |
| Bookmarks and traces | bookmarks hold selected terminal text and your note (0600), sent only over a signed-in socket and shown as text (`terminum-terminal.md` §9 Security; `terminum-agents.md` AC-98). `?trace=1` records no typed text, screen content, title or host name, in `~/.terminum/logs` (0600); `?trace=2` stays in the page (`terminum-terminal.md` AC-38) |
| Reboot restore | `layout.json` (0600) holds the layout; never output, history, environment or a command line other than a checked ssh recipe; only shells are started again (`terminum-lifecycle.md` AC-15) |
| Last lines (`lastLines`) | what a terminal printed (a token, a `.env` you displayed) is kept on disk for a shown pane's last lines, so it survives a reboot there, where tmux alone keeps it in memory only. Where they are kept, who reads them, when they go and what turns them off: `terminum-lifecycle.md` AC-96 |
| The update check | the only request terminumd makes by itself: one `HEAD` to the project's GitHub releases page a day; only a tag `vMAJOR.MINOR.PATCH` is kept and shown as text; nothing is downloaded or installed; `state/no-update-check` turns it off (`terminum-lifecycle.md` AC-17) |
| The installer and releases | `install.sh` and `terminum upgrade` verify the signature of `SHA256SUMS` with the release key they carry before the checksum, refuse root; releases are built and signed only on the maintainer's Mac from a clean `main` with locked dependencies (`docs/RELEASING.md`); each macOS terminumd is also signed with the maintainer's Developer ID as `io.terminum.terminumd` (no hardened runtime, not notarized), so the folder access macOS grants it, which every program in terminum's tmux inherits, is kept across upgrades and cannot pass to a binary signed by anyone else. An upgrade installs only what the key signed, and the key exists only on the maintainer's Mac (and its backups). Left: whoever controls the maintainer's GitHub account can replace a release's `install.sh`, which a *first* `curl \| sh` trusts; a program running as the maintainer while the Keychain is unlocked can sign |

Report a vulnerability privately through the repository's security advisories ("Report a
vulnerability"), not in a public issue. Include the version (`terminumd --version`), the
macOS and tmux versions, and the smallest reproduction.
