# v0.19.0 — A security audit: no sign-in in an address

A minor release: it changes the protocol between the page and terminumd (files are fetched
with the sign-in's header; terminumd no longer takes `?t=` in an address, and `/custom.css`
needs the sign-in), so the next minor after v0.18.1. Pages open from an older build reload
by themselves on the new one.

## Security

- **The sign-in never stands in an address.** An image's address carried the 30-day sign-in,
  which reads every file you can: Copy Image Address or Open Image in New Tab took it along,
  into history too. Images, videos, a document's stylesheets and downloads are now fetched
  with the sign-in in a header and shown from a `blob:` address.
- **An HTML file you view reads nothing else**: attributes it planted to have other files
  fetched with your sign-in are dropped.
- **Every answer carries the security headers**, a refusal too: no sniffing, no referrer, not
  kept, no camera, microphone, location, payment or USB, no other site's window or page
  holding or embedding terminum's answers.
- **Your `custom.css` is yours**: it needs the sign-in; before, any web page could load it.
- **A stronger password hash**: PBKDF2 with 600,000 iterations; an older hash is made again
  the next time you sign in.
- **Sign-in brakes**: a program on this Mac can no longer spend other devices' wrong-password
  allowance by naming their addresses on 127.0.0.1.

## Changed

- **Ask's Add to Chat leaves the view where it was**: the paste no longer scrolls to the input,
  so you read on from the text you asked about. Send to Agent still goes to the input.

## Fixed

- Checks that failed now and then under load: the menu's motion in WebKit, the speed of
  search and of bookmarks, a broken path's underline, the Files panel's oversized upload; a
  test of unreadable files that could hang instead of failing.
