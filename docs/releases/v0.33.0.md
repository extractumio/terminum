# v0.33.0 — Sessions that start with a prompt, runs that outlive tmux, fairer slots for schedules

A minor release: + Session on an agent's card takes a first prompt, a task's run goes on by itself after
terminum's tmux server ends, and schedules keep fewer slots, shared. terminum now wants tmux 3.8 or newer.
`terminum upgrade` brings it. How each part is used: `docs/USAGE.md`.

## New

- **+ Session takes a first prompt.** + Session on an agent's card opens a box under the pool: paste text and
  images, add files, drop task cards to name their IDs. Start opens that agent's session, and terminumd types the
  prompt once into that pane, through Dispatcher's gate. A miss is said, and the draft is kept. The box has its key
  to the whole window, as every box to type in has (AC-204, AC-184; TERM-524, TERM-592).
- **A run outlives its tmux server.** When terminum's tmux server ends (a crash, a reboot), a task Dispatcher was
  running, in progress, goes on by itself in a new window, and its agent is told the session was resumed. A window
  you closed, a task waiting for you, + Session's sessions and your own are not resumed. A second end of that server
  within an hour resumes nothing and says why (AC-205; TERM-531).
- **New task has a Type,** beside Severity, none chosen until you pick one (AC-199; TERM-492).
- **The limit of open tasks agents may make in a project** is 10,000 by default and is set as `agentOpenTasks` in
  `settings.json`. It was 200, which a busy project reached; the refusal says where the limit is set (TERM-542).

## Changed

- **Schedules keep fewer slots, shared.** An agent keeps one slot for every two of its schedules not paused
  (ceil(N/2)), shared by all of them, not one per schedule; its card's rings say "kept for N schedules", and
  integration's slot stays besides. More slots are left for your runs. A schedule's task starts at once in a kept
  slot, else in an ordinary one, else closes an idle session of its own schedule, else waits ahead of every other
  wait of its agent and project: a manager's promotion stops behind it, and a drag ahead of it is refused. A newer
  firing or Run now of a schedule supersedes its task still waiting for room (FAILED, "Superseded by …"), unless you
  ran that task yourself, and "session still busy" no longer skips a firing. Adding, unpausing or moving a schedule,
  or lowering an agent's at once, is refused by the new count, integration's slot included (AC-161, AC-162; TERM-574).
- **The board names its sections on rails:** Agent Pool, Routines and Task Management. The pool and Routines fold by
  their rails to a strip that keeps its +, and add tiles follow the last card. "Scheduled" is "Routines" on the
  board. Waiting lines show their project's stripe and name (TERM-524).
- **The session list's head key is [+ Session]:** an agent's session in the project in view, a projects menu
  otherwise. The tmux New session key stays at the list's foot (TERM-524).
- **A session in no project goes to the top of its tmux group** when its agent takes a message, as a project's session
  goes to its project's top: its window moves first in tmux, and its row glides there. The windows of projects'
  sessions keep their places, and a session you attached by name, on this Mac or a host, is never moved (AC-92;
  TERM-491).
- **terminum wants tmux 3.8 or newer.** Before it, a tmux server can crash while terminum is attached (a session
  ending while a window change is queued, as when two windows' programs end at once), ending every terminal in it.
  `terminum install` and `terminum status` say so when terminum's running tmux server is older. The running server
  keeps its version after `brew upgrade tmux` until it restarts (TERM-485).
- **A session opened from a screen of another size keeps its size until a key is typed there:** where a coding agent
  draws on the normal screen, only the page that types sizes its window, and a page that only looks re-flows it. The
  log names each resize (`sizing.resize`) (AC-13; TERM-555).
- **A red check of a queued task is tried on the target first.** When a task's Verify fails, terminum runs the
  failed steps on origin/main. When they are red there too, the task stays queued behind one P1 Bug task for the red
  target and runs Verify again once that task is DONE or FAILED; it is told if it leaves the queue meanwhile, and told
  to integrate again when the Bug task ends. When they pass there, the task goes back naming them (AC-198; TERM-448,
  TERM-569).
- **A batch's After that cannot run now** (a release runs, or the project's folder holds uncommitted changes) waits
  and runs again by itself, instead of failing and holding the queue for a human. A failed After has an After again
  key, whose green run ends the batch's task without a Close (AC-191; TERM-461, TERM-466, TERM-289).
- **Integration moves a project's folder only when `git status` is empty:** an uncommitted change, an untracked file or
  a changed submodule, whatever git's config hides, makes After wait (TERM-289).
- **The README presents terminum as an IDE for running a project on coding agents:** the path from a task to a
  checked, published commit, in three steps with the switches named. The README, the guide (`docs/USAGE.md`) and
  `SECURITY.md` say the same in far fewer words; what only `SECURITY.md` held is in the specs' Security sections
  (TERM-525, TERM-532, TERM-533, TERM-534, TERM-539).

### For contributors

- **`make release` and `make rehearse` run in their own trees** (`.worktrees/release`, `.worktrees/rehearse`) at a
  commit pinned on origin/main, never in the primary checkout. The pin defaults to the newest commit with a full pass
  in 48 hours (`PIN=` chooses one), and the notes are read from origin/main. `make check` keeps a pass per step and
  content, so a second run after a red step runs that step only. The full run's steps see an allow-listed
  environment. A check of real programs gets one unchanged retry when its code did not change since the last full
  pass, and is named in the notes. A time budget over under the run's own load is said, judged by
  `make check CHECK_ARGS=--timing`. `/simplify` and `/docs-review` leave the release for a weekly review, and a nightly
  schedule rehearses origin/main (AC-200, AC-201, AC-202; TERM-486, TERM-494, TERM-467).
- **`make land` moves the primary checkout only when it is clean** (`git status --porcelain` empty), and says so
  otherwise (TERM-279).
- **`make install` waits for the install turn** instead of failing while integration's own install runs, and says
  whose install it waits for. `make -n install` runs nothing. `make build` then `make install` compile terminumd once
  (TERM-396, TERM-588, TERM-227).
- **The repository's rulesets** forbid force-pushing or deleting `main`, and updating or deleting `v*` tags. CI's
  Actions are limited to GitHub's own, pinned by SHA, and its Rust installer is pinned by version and SHA-256
  (TERM-537, TERM-538).
- **An outside pull request is told to sign off every commit, and checked** (`scripts/check_signoff.py`; TERM-553).

## Fixed

- **A schedule or a run set by a project's manager is said to be the manager's,** no longer "set by a human" or "The
  human ran task …" (TERM-433). v0.32.0 named this under Known.
- **RUN no longer refuses a task whose linked session closed** ("Unlink the session to run it"). A pane on a tmux
  server terminum does not read still refuses (TERM-552).
- **Claude Code's answer no longer stands two or three times in a session's history** after a phone looked at a Mac's
  session, or the window, Files or a split changed the view. A history damaged before stays (TERM-555).
- **When terminum's tmux server ends,** tasks queued for integration stay queued instead of going FAILED; a Check,
  Verify or Publish lost with its window runs again, and is never read through another line's window. An After lost
  with its window is not run again: a P1 task "After's outcome is not known for batch N" asks you to check its work.
  A run whose link was dropped when the server started anew no longer leaves its task IN PROGRESS for good (TERM-531,
  TERM-549).
- **A draft typed in a finished task's session keeps it open:** the close 5 minutes after DONE reads the agent's input
  box first (AC-125; TERM-248).
- **A Claude Code scheduled wakeup in a task's session is not taken for your new work,** so it no longer takes a queued
  task out of integration (TERM-474).
- **A red batch's integration agent starts at once:** its project's agent limit no longer holds it, and the previous
  integration task's closing session holds no slot (AC-194; TERM-500, TERM-518).
- **A red batch built anew keeps its red round,** instead of rewriting it as "moved" with a wrong reason and end time
  (TERM-501).
- **A running tool's long command no longer makes a remote Linux pane jump** every 0.6 s: the fold rules know Claude
  Code's Linux dot "●" as well as "⏺" (AC-32; TERM-600).

### For contributors

- **The trees kept for warm builds** (the integration queue's candidate tree, `.worktrees/release`,
  `.worktrees/rehearse`) keep `terminumd/target` under 20 GiB. At the candidate's Check, and when a release or
  rehearsal takes its tree, the object files each incremental build on macOS leaves beside the next build's go first;
  the current build's stay, so builds stay incremental. A target still over is cleaned, its dependencies' builds cloned
  from the primary checkout again. A build running there is never cleaned under it (AC-206; TERM-603).

## A correction to v0.32.0's notes

v0.32.0's notes were written before its last commits. These shipped in v0.32.0 without a word in its notes:

- A card's Run key stands only on TODO cards; a task in another column runs again from its window, with a comment (a
  drop on an agent still runs it). Find stands in TODO's head ("Filter all columns") wider than a phone. A column's
  sort is a segmented control, each card says when it last changed, a tab's count stands on its name's baseline, and
  a panel row's cards are equally tall. A folded TODO card no agent ran no longer shows its Run key on hover
  (TERM-397, TERM-374).
- The project window's Auto-Dispatch tab says what each choice does and aligns its fields (TERM-151).
- In Safari, the project window opened on a tab other than General shows that tab's panel as visible; it read hidden
  before, though its contents were painted (TERM-445).
- The integration queue verifies three tasks at once, checks and publishes the next batch while the previous batch's
  After runs, and keeps each attempt's Prepare and Verify log; an integration notice keeps its identity when its
  commits change (TERM-446, TERM-447, TERM-449, TERM-450).
