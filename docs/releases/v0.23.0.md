# v0.23.0 — session plans and progress, notes for you, agents on ssh hosts, last lines kept, links that open

A minor release: new features (a coding agent's plan, progress and notes in the list and a Plan
pane; `terminum mcp`; the same for agents on ssh hosts; a session's last lines after a restart)
and an install or upgrade that keeps the agents' integration current. Read **Before you
upgrade** first.

## New

- **Session plans and progress.** A coding agent's plan shows as a percent and a thin track on
  its session's row, on the header's Plan button and as a circle in the floating buttons'
  column. Press any of them to open the
  Plan pane: the items (✓ done, ▶ in progress, ○ pending, ⚠ blocked), the current step and the
  agent's ETA ("~17:40 (agent's estimate, given 16:55)"). The plan comes from the agent's own
  plan tool through terminum's hooks (Claude Code's tasks and TodoWrite, Codex's update_plan
  where it has one; Codex 0.164 has none and keeps its plan through terminum's MCP tool). The
  percent is completed of all items, never the agent's guess.
- **A reminder, never typed.** When a working agent has not updated its plan for a while
  (10–30 min by the turn's length), terminum asks it once through the hook's own channel;
  nothing is typed into the pane. Seen in real sessions: Claude Code 2.1.310 updated its plan
  3 s after the reminder, Codex at once.
- **Notes for you.** The agent leaves bugs, deferred work, follow-ups and questions; the Plan
  pane lists them under the plan with Done, Reopen, Delete and Insert into chat (pastes the
  note into the pane's input, never Enter).
- **`terminum mcp`**, terminum's MCP server (update_session_plan, get_session_plan,
  add_notes_for_user, update_notes_for_user). `terminum hooks install` adds it to Claude Code
  (inside terminum's plugin) and to Codex (one marked block in `~/.codex/config.toml`, backed
  up first). Outside a terminum pane it offers no tools, so other sessions pay nothing.
- **Coding agents' progress on ssh hosts.** `terminum hosts agents <host> on` (or the host
  menu's "Coding agents' progress on <host>…") installs the hooks and MCP server on the host,
  one result line per agent; that host's rows and Plan pane then show its agents as local ones.
  The events ride on the Files helper's ssh as a reverse socket forward; nothing is written to
  the host's `~/.claude` or `~/.codex` before you turn it on, and `off` takes it out.
- **Links with a text of their own open.** A link a program prints with its own text (an OSC 8
  hyperlink, such as Claude Code's "⧉ … MR !318") is underlined; hover shows the address,
  ⌘-click or a tap opens an http(s) address in a new tab or a file path as a printed path does.
  Other schemes stay text. tmux 3.6a ends such a link at each row's end, so a link that runs
  past a row is a link on its first row only; tmux before 3.4 keeps no such links at all.
- **OpenCode's mark** stands beside its sessions in the list and the header, as Claude Code's
  and Codex's do.
- **A calmer header on a computer.** The session's title, ✎ and a Plan button (with the
  percent) are keys of the header's size on the line of its other keys; the title and folder
  line up with the terminal's text, the session list's first group with the terminal's top. The
  floating buttons' column shows the plan's progress as a circle, and fades while you scroll.
- **Sessions waiting for your answer** are lines across the terminal's top, one each, under
  the banners, instead of cards over its corner.
- **Last lines survive a restart.** terminumd keeps each pane's last 300 lines (setting
  `lastLines`, 0–2000, 0 off); after a reboot or a killed tmux server, the row's menu has
  **Show Last 300 Lines** with what the pane showed before (a coding agent's last turn, say),
  and the restore report points to it.

## Before you upgrade

- **The agents' integration is refreshed, only where you installed it.** Where you ran
  `terminum hooks install`, an install or upgrade now updates Claude Code's plugin (adding the
  MCP server and a synchronous PostToolBatch hook that carries the reminder) and adds Codex's
  MCP block; an agent without terminum's hooks gets nothing. Not wanted: `terminum hooks
  remove`. A failed refresh is a warning, never a failed upgrade; `terminum status` names
  `terminum hooks install` until it is fixed.
- **Codex asks once to trust terminum's changed SessionEnd hook** in `/hooks` (it was async,
  which Codex warned about at each start); trust it there.
- **Restart running agent sessions** (Claude Code and Codex): they read their plugins and
  `config.toml` only when they start.
- **Hosts are off until you enable them**, one at a time: `terminum hosts agents <host> on`.
  The host's sshd must allow forwarding a Unix socket (`AllowStreamLocalForwarding`, and
  `AllowTcpForwarding` on Alpine, whose stock value is `no`); a refusal is shown as
  "forwarding refused by <host>'s sshd" and asked again every 10 minutes. `DisableForwarding
  yes` or `AllowStreamLocalForwarding no` refuse the Files tunnel too; only a refusal of this
  forward alone (`AllowStreamLocalForwarding local`) keeps Files working. Dropbear forwards no
  Unix socket, so Files fail there too.
- **Rolling back or uninstalling.** `terminum uninstall` takes the hooks and the MCP server out
  of both agents. `terminum rollback` leaves them as they are: they run
  `~/.terminum/bin/terminum`, which a rollback never moves (it stays the newest build's), so an
  MCP tool the older terminumd does not know fails as a tool error. `terminum upgrade --to` an
  older release does move that command, and an older build has no `terminum mcp`: run
  `terminum hooks remove` first (then `terminum hooks install` with the older build), or Codex
  and Claude Code report terminum's MCP server as failed at each start.
  `state/plans.json` and `notes.json` stay on disk, unread by older builds.

## Fixed

- **Typing into a full-screen program that uses the mouse** (OpenCode) reached nothing after a
  click on the terminal: the keys stayed where they were. A click there now gives the terminal
  the keys, as anywhere else.
- **A long drawn table** was split in two while it was redrawn; it is read whole.
- **An older helper on a host** was never replaced by a newer one; it is updated again.
- **A long tap's menu on a phone** no longer takes the keys: the keyboard stays up.
- **A tmux server's first start answered every later command with the one before it** (since
  0.21.0): setting the server's identity answered twice on a server without one. Now set once,
  one answer; also in the restore.
- **Enabling Files on a host whose login shell prints** (an `echo` in `.bashrc`, common on
  Debian-style hosts) failed: the helper's answer was compared with all of ssh's output. Only
  its last line counts now; probes read after a marker.
- **Codex warned at each start** about terminum's async SessionEnd hook; it is synchronous now.
- **An upgrade updates Claude Code's plugin in place** instead of removing it first; a failure
  keeps the old one.
