# v0.6.0 — a design code, and a better phone

## Changed

- **A new look, from one design code.** `web/static/tokens.css` names every spacing step (a
  4px grid), surface, radius, type size and timing, and `docs/UI-GUIDELINES.md` says how
  they are used. On every screen:
  - elements are set apart by space and by a step of background, not by 1px lines;
  - buttons, menus, forms, dialogs, fields and the header bars have slightly bowed, hand-drawn
    edges, and round buttons are never exact circles;
  - a hover changes color; a press shrinks and flattens a button, its release swings back
    with a ripple; menus, forms and dialogs come in with a short rise. Nothing moves inside
    the terminal, and the system's "reduce motion" turns it all off;
  - tables, code, Markdown and images drawn inside the terminal (and in View) follow the same
    rules: no frames or column lines, a hairline between a table's rows.
- **A session's bar is its folder's color.** Each working folder gets its own pastel hue,
  as far from the others as their number allows; sessions in the same folder share it, and a
  folder inside another gets a hue near its parent's.
- **Which coding agent runs in a pane** shows by its mark beside the session and in the
  header (Claude Code, Codex), else a terminal icon. The marks are Anthropic's and OpenAI's
  trademarks, outside terminum's licenses (`NOTICE`).
- **A group's state line has one look:** a colored dot for how bad it is and terminumd's
  words. A session waiting on a host that is down shows that host's state.
- **On a phone, a tablet or a narrow window** the list's four buttons are one row of icons
  with short captions, and tap targets are finger-sized on an iPad too.
- The terminal's text is one size bigger by default (15). An installed theme keeps its own
  size: change `size` in `~/.terminum/themes/*.json`.

## Fixed

- **The phone's keyboard and the hot keys no longer stack up** over the line being typed:
  the on-screen keyboard closes the hot keys, and opening the hot keys puts the keyboard
  away. With a hardware keyboard (an iPad's) the hot keys stay open while you type.
- **Hold and slide moves the cursor**, however long the finger rested first; in an agent's
  input box the cursor follows the finger onto the character under it, over its lines too.
- An agent's status lines stayed in sight after the hot keys opened; they wait behind ⓘ
  again.
- A file's View stayed on screen when another session was shown. Each session now has its
  own View, back as it was when you return; a closed session's View goes, unless it holds
  unsaved edits.
- A table copied without its top rule (`│ … │` first, then `├─┼─┤`) is shown as a table.
- Esc closes a host's menu. A theme whose cursor color is close to its background keeps a
  visible focus ring. Leaving a name field in Files no longer cancels the next one.
- `terminum upgrade` and the installer set the package's file modes themselves (0755 or
  0644), whatever the user's umask; a hard link in a package is refused.

## Upgrading

`terminum upgrade`. Nothing to migrate.

## Validation

The following pass on the released tree:

- Rust unit tests and `cargo clippy` with no warnings; UI, page and script unit tests
  (`make test`).
- The protocol checks against a private terminumd and tmux server: core, access, restore,
  sizing, the WebSocket, remote hosts, your own sessions here and on a host (stand-in ssh).
- The page's browser checks in Chromium and WebKit, at a wide and a phone size, including the
  new look and motion checks. The Files panel's browser checks, and the live checks against a
  private tmux server.
- `scripts/security_check.sh`, and the installer's check in a temporary home.

Not checked: a real sshd for remote hosts; an iPhone or iPad itself. The touch checks drive
an emulated phone in Chromium: whether iOS lets a finger held past its own menu's delay still
slide, and how tall the on-screen keyboard leaves the page, were not measured on a device.

Known limits:
- The folder colors are worked out from the folders open now, so opening a new, unrelated
  folder shifts the others a little.
- A Files View of a session that closed while it holds unsaved edits stays in the page until
  it is saved or the page reloads.
