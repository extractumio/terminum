# v0.25.1 — Finder drops by their own paths, the panes as View's window, no image buttons

A patch release: fixes and changes to what is already there (how a drop is pasted, where the
floating buttons' panes open, a mark for a session done with a shell still running); nothing
new to install or upgrade.

## Changed

- **Files dropped from Finder on a pane of this Mac paste their own paths**, at any size,
  folders too: nothing is uploaded (two zips, one over 100 MB, were uploaded as copies and the
  large one refused). terminumd finds them on macOS's drag pasteboard, matched by name, kind,
  size and time. When it cannot (a drag from Mail or a browser has no file on disk), copies are
  uploaded as before and the toast says which case it was: the drag held no file, a name is
  not among the drag's files (and what it held), the file of that name differs (its size, or
  its time "3 h apart"), it cannot be read, a path has a control or invisible character.
- **Bookmarks, Reminders, Sent and Plan open as one window**, placed and drawn as View's: 12 px
  under the terminal's top, 16 px over its end, left of the floating buttons, 820 px wide at
  most, View's head, type and corners; on a phone each is a sheet as before. The bookmarks'
  Done is **Resolve**.
- **No image buttons after image paths in the terminal.** A path to a picture is a path as any
  other: underlined, a click opens it in View. (On a long row each button stood alone on an
  empty line.)
- **A session done with a shell still running** (Claude Code's "· 1 shell still running", past
  the 10 minutes such work keeps it working) shows a quiet terminal mark on its row and in the
  header while its footer counts the shell, monitor or task; it is done, unread and reminded
  as before.

## Fixed

- **A host group's ⋯ menu** near the session list's end went past the window's bottom; it
  stays inside the window.

## Verified

(cargo 648, the Panel's 38 and the Page's 137 unit tests), clippy clean, the Panel's browser
check (160), the Page's 1495 browser checks (Chromium and WebKit, a wide and a phone size),
`scripts/e2e_agentstate.py` (11), `scripts/e2e_hooks.py` (32), `scripts/e2e_remote.py` (32) and
`scripts/security_check.sh` pass. `web/test/e2e_live.mjs` passes in WebKit alone (91) and in
Chromium; run with both, three of its WebKit checks (AC-32's fold of a tool's output, AC-93's
Mark as Unread) fail after Chromium's, as they did on 6625162, before these fixes. A drop from Finder on
this Mac pasted the file's own path. Not verified: the new toasts after a real drop from Mail
or a browser, the windows on an iPad.
