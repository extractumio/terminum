# v0.34.0 — The Project Supervisor, the Inbox, answers in one press

A minor release: each project can have a Supervisor that finds its problems, sizes them, proposes or drives fixes
and checks that they stay fixed; agents' and routines' reports go to an Inbox of their own; a task waiting on its
agent's question is answered in one press. `terminum upgrade` brings it; run `terminum hooks install` (or let the
upgrade refresh the hooks) for the new onboarding skill. How each part is used: `docs/USAGE.md`.

## New

- **The Project Supervisor** (project window › Supervisor, off until you turn it on). Code watches the project's
  store every ten seconds and its git tags, gate records and approved probe commands once a day, and raises signals
  with their evidence, measure and response level (Record, Digest, Card, Incident). A Card or Incident level signal
  gets an investigation round by a tier agent of the pool you choose (small, medium, strong), which returns a
  checked finding; code reruns its queries before keeping it. The **Problem register** ranks measured problems with
  their hypothesis, fix options and tasks; **Accept as is** keeps your ruling until new evidence. Fixes are funded
  highest impact first within a budget; tasks the Supervisor makes carry its mark, and a human's or manager's action
  on a task wins over it for 24 hours (AC-211 to AC-263; TERM-682 and its pieces).
  - **Levels you choose**: Observer reads, Advisor also proposes and reports, Operator may also act. An Operator's
    **holds** stop a marked run, pause Auto-Dispatcher or integration, or take a task out of integration; each needs
    current evidence, names its undo, and a held task gets one comment with it (AC-231, AC-232, AC-241, AC-245;
    TERM-695, TERM-699, TERM-789).
  - **Critical incidents** show a red bar on every signed-in page and pin first in WAIT FOR HUMAN, with a timeline,
    **Acknowledge** and **Snooze 1 hour**. A **Critical line** sends fixed messages (IDs, levels, counts; never task
    text) through executables you name, with quiet hours, a repeat ladder and a second channel (AC-224 to AC-229,
    AC-263; TERM-690, TERM-692, TERM-734).
  - **Decisions and the weekly review**: a checked, high-impact choice that is yours opens a WAIT FOR HUMAN card with
    options, evidence and the cost of waiting; lesser ones go into a weekly review a Strong tier agent writes, which
    reaches you as one report. An incident's **Thread** and **Talk** let you discuss it with the strong agent; a
    **Record owner ruling** suppresses the same evidence (AC-240 to AC-244; TERM-698).
  - **It is measured too**: rule outcomes after a day, a week and four weeks, a breaker that pauses a rule you mark
    **This is wrong**, independent reflections by an agent of another tier, pool agent scorecards, a Supervisor
    scorecard and a quarterly audit; configuration changes are replayed against retained history before they apply
    (AC-246 to AC-262; TERM-700 to TERM-706, TERM-786, TERM-787).
  - **Starting a project**: four templates (Open-source tool, Commercial app, Prototype, Internal tool) fill a
    settings draft; import and export move preferences between projects; `terminum supervisor replay --project <ID>`
    shows what it would have found in the retained history, without starting any agent (AC-215, AC-220, AC-221,
    AC-263; TERM-688, TERM-707).
  - Among its detectors: a red target tied to a never line (`flow.main_red`), stuck work left IN PROGRESS after its
    agent stopped (`flow.stuck`, handed to WAIT FOR HUMAN when the step left is yours), a P0 task waiting in TODO
    (to Card level after 24 hours, Incident level a day later, both set per project in whole hours), review gates for
    the surface map's T2 and T3 paths, outside indicators and unanswered feedback from your probes (AC-212, AC-213,
    AC-250 to AC-252, AC-262; TERM-784, TERM-782, TERM-931, TERM-1002, TERM-1003).
- **The Inbox.** Reports, what agents, routines and the Supervisor give you to read, stand in the Inbox at the top of
  the board's session list: unread in bold, critical in red and first, each row with its type and sender. A report
  opens over the board and reads as the Files viewer shows a document; open 2 seconds, it is read; Delete has Undo
  and 30 days to restore. **Reply** under a report made in a task's run goes on in that task's conversation as Run
  with your words does. A routine's result becomes a report. A critical report raises a red line once, or, with the
  Supervisor on, opens its subject's incident. Agents write by `create_report` and its sibling tools; a worker only
  on its own task, at most 10 an hour (AC-265 to AC-280; TERM-822, TERM-876, TERM-952).
- **Answer a waiting task in one press.** A task waiting on its agent's question shows **Answer** (in Run's place),
  **Continue with Recommended** and **Archive**, whoever ran it and whether its session lives. A listed option is
  saved in one press and its ID goes with the answer. In a live session you opened, terminum types fixed words with
  the task's ID (never your text) once the agent's turn has ended; elsewhere it goes on as Run. A question asked
  before the upgrade carries no asking conversation: answer it in its task's window (AC-285, AC-230; TERM-693,
  TERM-980, TERM-987).
- **Onboard a project**: type "onboard my project" in a Claude Code session of the project. The `terminum-onboard`
  skill in terminum's plugin reads the folder, asks you once, fills only what is missing (pool agents, routines,
  agents at once, a Supervisor charter draft) and lists the presses left to you. New manager tools:
  `get_project_setup`, `update_project_setup`, `set_supervisor_charter` (AC-283, AC-284; TERM-968, TERM-975).
- **A new comment reaches the task's working agent** on its next prompt or tool call, in fixed words with the task's
  ID and who wrote it; each comment says whether its session was told. A fresh start carries the task's comments
  (AC-209; TERM-621, TERM-623, TERM-624).
- **An agent can wait for another task** (`wait_for_task`) instead of asking you: the other tasks join its Blocked
  by, it waits in TODO with no clock, and Dispatcher goes on with it once they are DONE (AC-210; TERM-643).
- **A window's buttons have keys**: ⌘⇧ and the underlined letter of the label (Ctrl+Shift off a Mac), ⌘⇧↩ for Run,
  Esc for Cancel; Run and Archive close a task's window (AC-281, AC-282; TERM-948).
- **Files opens any folder** by its typed path in the pane's folder's place, through a cd, a pane switch and a
  reload, until Back (AC-275; TERM-825).
- **A run that terminum serves less well** (a Codex under a shared app-server, an agent in its full-screen TUI) gets
  a window once saying what is lost and how to start it otherwise, with Do not show again. Under a shared Codex
  app-server, `terminum mcp` offers one tool saying why it has no terminum tools (AC-207, AC-208; TERM-616,
  TERM-620).
- **Ctrl+Shift+C and Ctrl+Shift+V copy and paste in the terminal on Linux and Windows**, with the browser's clipboard;
  the plain Ctrl keys stay the terminal program's, and Settings turns the pair off (#9; TERM-678).

## Changed

- **+ Session's Start keeps the board**: the draft clears and a line under the pool says "Session started on <agent> ·
  Open the session". The box folds at Start and comes back on a failure; its keys stay in view in a short window
  (AC-204; TERM-951, TERM-966, TERM-977).
- **The board**: agent and routine cards use every track and the browser's whole width, in equal columns that wrap;
  phone sections stack. The Inbox is a panel of its own. A project's header in the session list opens its board; a
  session row's right side aligns on a grid (AC-92, AC-267; TERM-827, TERM-880, TERM-881, TERM-952, TERM-954).
- **A session you attached by name**, on this Mac or a host, goes to the top of its tmux group when its agent takes a
  message, as other sessions do; v0.33.0 said it was never moved (AC-92; TERM-793).
- **Confirmed Give up** interrupts the run's Claude Code or Codex and sends it a fixed request to stop background work
  and subagents and end its turn; the conversation, shell, window and queued commit stay (AC-138; TERM-826).
- **A manager's stop puts the task back in TODO**, and a called-off wait frees its run. A manager must confirm before
  reopening a DONE task (TERM-917, TERM-677).
- **Results and reports are asked for as Markdown with `##` headings**; a comment's label lines read as sections
  (TERM-896, TERM-714).
- **Questions to you** are asked in plain words read once: one decision a question, every internal name explained
  (AC-157; TERM-1005); agents are told to `ask_human` when the step left is yours (AC-155; TERM-1002).
- **A queued task stays queued** when its agent asks, waits, moves or finishes it; a red target's failed steps run
  again and end its Bug task when they pass (AC-187, AC-198; TERM-650).
- **Integration refuses an integration agent without enough kept slots**; Publish and Cleanup commands have a
  deadline; Dispatcher's waits for each tmux run are bounded (TERM-596, TERM-456, TERM-423).
- **A human's Run now of a schedule is credited to that human** (TERM-529).

### For contributors

- **A Python runner's e2e check runs** in the targeted pass when its `*_checks.py` modules cite a touched case or
  change (AC-104; TERM-859). Busy Cargo profiles are skipped when a new tree clones caches (TERM-453).
- **Build folders stay bounded and out of Time Machine**: every checkout's cargo target is excluded from backups;
  only folders over the bound are emptied, debug first, under their held locks (TERM-916, TERM-920).
- **Leftovers**: a step's tmux server ends before its folder goes, `scripts/leftovers.py` ends test tmux servers
  whose socket is gone, the files Docker's VM keeps from old bind mounts are released, and the guard's cleanup keeps
  valid macOS cwd records (AC-102; TERM-725, TERM-907, TERM-912).
- **Linux CI** has a bounded hour and documented memory limits (TERM-720). The nightly full run is kept as a fresh
  flake sample (TERM-520). The memory hook takes its line caps from `project-memory/RULES.md` (TERM-956).

## Fixed

- **A FAILED belongs to its own run**, not to a launch later in the same second (TERM-716).
- **A run's saved human comments** go with its continuation; every task carried by a queued RUN is protected
  (AC-122; TERM-196, TERM-373).
- **Auto-Dispatch Off** is honored before ordered starts (AC-170; TERM-236).
- **The silent-subagent watchdog** pauses while a run waits (AC-127; TERM-639).
- **Codex's saved conversation** is kept until a prompt confirms another (TERM-673).
- **A task's draft attachments** stay when reading the task's files fails (AC-109; TERM-231).
- **Files**: folder rereads stay bounded under continuous changes (AC-61; TERM-79).
- **An asked quote keeps its wavy line** when the history is numbered anew (TERM-776).
- **The Supervisor's own counts**: a signal counts its repeats, not every evaluation pass (counts already inflated are
  reset, schema 65); an accepted problem stays accepted until its signal counts a new repeat, or until a level reading
  has stayed clear for its window; a fix task archived before it ran frees its problem for one new task (AC-211,
  AC-236, AC-238; TERM-796, TERM-801, TERM-812, TERM-899).
- **v0.33.0's Known item**, a published integration batch later saying nothing was published (TERM-337), was fixed
  in v0.32.0 (TERM-447); the line was out of date.

## Known

- An Auto-Dispatch agent round already under way can still start a task after Off (TERM-652).
- An interrupted Run can type a task's comments again after Enter (TERM-675); an unfinished subtask can cancel a
  prerequisite's continuation (TERM-674); `take_task` on a member of a queued RUN can keep the press from starting
  (TERM-662); in a run of several tasks, Dispatcher's idle and budget failures can move a waiting one (TERM-654).
- Files can keep stale rows after a slow refresh ends (TERM-660).
- Integration: a stalled git command blocks both lanes (TERM-659); failing to open an After or Cleanup window can mark
  a published batch red (TERM-658).
- The Supervisor's `owner.priority_churn` fires on ordinary owner starts in a project with no history (TERM-1018).

## If you ran a build of `main` between the releases

The store migrates by itself (schema 65). Every task that waited in WAIT FOR HUMAN with its report becomes a report in
the Inbox, unread, and its task DONE with a comment linking it (AC-274). Supervisor problems an older build reopened
on a mere repeat stay "recurred": accept them again.
