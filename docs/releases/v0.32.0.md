# v0.32.0 — A board of tasks that agents run: Kanban, Dispatcher, schedules, integration

A minor release, by far the largest: beside the sessions terminum now has a board of tasks, a
Dispatcher that runs them on coding agents, schedules, a queue that integrates finished work, a
message history and a dashboard. New pages, a store of its own (`~/.terminum/state/kanban.sqlite`)
and a changed protocol make it the next minor. `terminum upgrade` brings it. How each part is used:
`docs/USAGE.md`, "Tasks".

## New

- **Kanban at `/kanban/`.** Tasks in TODO, IN PROGRESS, WAIT FOR HUMAN, FAILED and DONE, each with an
  ID of its project (TERM-7), a type (Feature, Bug, Debt, Story), a severity, an owner, Markdown text
  and comments, files up to 100 MB, one level of subtasks, an external link, a target, and Blocked
  by and Follow-ups lists (kept and shown; they order nothing yet). TODO stands as a column of its
  own, the other columns one at a time under tabs with their counts; a phone shows one column. A
  task starts from + New task, a file dropped on the board, a terminal's selection, a bookmark or a
  reminder. Projects are shared with the session list, which stands left of the columns. A card
  with a live session carries that session's row, and a press opens it. DONE archives itself after
  2 days.
- **Agents work the board** through `terminum mcp`: `list_tasks`, `get_task`, `create_task`,
  `take_task`, `move_task`, `update_task`, `link_task`, `add_comment`, `attach_file`, `get_file`,
  `ask_human`, `finish_task`, on the tasks of their project. What an agent notices and leaves
  undone becomes a task, in the sections of the project's template; an agent's bug is never below
  P2. A question to you comes by `ask_human` in three parts (why you are needed, the recommended
  answers, the details) and the task waits in WAIT FOR HUMAN.
- **Dispatcher runs a task on an agent.** Each project has a pool of agents: a name, Claude Code or
  Codex, the command that starts it, an effort, how many may run at once. Press Run, or drop a task
  (or several) on an agent: Dispatcher opens a window in the project's folder, starts the agent by
  its command, gives it the task, moves the card as the session lives, asks for a result in fixed
  sections and closes the session 5 minutes after it ended. A task's budget ends the agent at its
  limit; a session over the memory limits (4 and 8 GiB unless set) is warned, then ended. A card
  shows its session's CPU, memory, running time and tokens. Answer a waiting task in a comment and
  press Run: the same conversation goes on. Run on a task with subtasks takes those not DONE into
  the same session. Sessions on remote hosts run the same way.
- **An agent's queue.** Run on a busy agent offers its queue; the task starts by itself when a slot
  frees. The agent's window shows the queue, ordered by a drag or its arrows.
- **Subscription limits on the board.** Each agent shows two stripes, its subscription's five-hour
  window and week, read by a usage command that spends no tokens, and by `terminum statusline` for
  Claude Code, which you add to Claude Code's status line yourself (`docs/USAGE.md`, "Subscription
  limits on the board").
- **Auto-Dispatch,** off until you turn it on for a project: it starts TODO tasks by itself, either
  by an agent's scoring or by priority and saved order. It takes P0 and P1 that stood 10 minutes in
  TODO, 10 tasks in 24 hours at most, unless set otherwise; a failed round or two failed tasks turn
  it off, and its switch says why.
- **Schedules.** A schedule holds a text, an agent, a time budget and a cadence (every N minutes or
  hours, days of the week, a day of the month, once, or five cron fields). When due, Dispatcher makes
  a task from it (S_TERM-8) and runs it; a firing while its last task still runs is skipped, one
  missed while the Mac slept is not run on wake. Run now starts one at once. `/scheduled/` lists
  every firing with what went in and what came out.
- **The integration queue,** off until you turn it on in a project's window. An agent queues its
  task's commit with `integrate`; terminumd builds batches of the commits that merge together, runs
  the project's Check on each, publishes a green one (its own push, never forced, or the project's
  Publish command) and gives a red one to the project's integration agent, which returns the task
  that broke it, checks again or adds a fix. The INTEGRATION column shows the batch in work and the
  queue; a card's ⋯ menu and a drop on the column queue a task or take it out. An IN PROGRESS card
  says "overlaps <ID>" for a task whose commits do not merge with its own.
- **Managers and workers.** The session + Session starts for a project, or one you open in a
  project, is its manager: its tools run the project's tasks on the pool's agents, answer and stop
  them, keep the pool and the schedules, and list, read, type into and close the project's other
  sessions. Every other session is a worker and neither finds nor runs these. `terminum tools`
  and `terminum tool <name> '<json>'` run the same from a shell; `terminum tokens` makes a token
  for a program outside terminum. Roles guide agents and are no wall against a program of yours: a
  manager does in its project what you do on the board, with no window shown to you first
  (`SECURITY.md`, "A project's manager").
- **Message history at `/history/`.** Every prompt and command sent, found by its words, each row
  saying who sent it (you, Dispatcher, a manager) to which agent or shell, in which session,
  project and tasks, beside quick filters with counts.
- **The input log.** Everything terminum writes into a pane is a row of `inputs` in the store, kept
  180 days: what you type (a row per Enter), paste or the Files panel types, and what Dispatcher
  pastes. A password prompt's input, or a line begun with a space, keeps only why it is not kept.
- **Dashboard at `/dashboard/`.** Four tabs over a day, 2 weeks, a month, a quarter or a year: You
  (active time, engagement, load), Tasks (your share of the operations on tasks beside the agents'),
  System (Dispatcher's sessions and how their tasks ended), Costs (tokens and list-price dollars of
  Dispatcher's sessions). For it the pages count what you do by the minute, how many presses, keys
  and scrolls and where, never which key or what text, into `user_interaction`, kept 180 days.
- **The idle agents' exit,** off by default (Settings): Claude Code or Codex left idle in a row no
  page showed for the days you set is ended; its shell and session stay, and the pane says which
  agent and session it was, its command line and folder, and the command that resumes it with the
  options it started with.
- **One switcher of sections** (Sessions, Kanban, Dashboard, Messages) in every page's top left
  corner.
- **A key in the corner of every text box** shows it over the whole window; the key or Esc gives it
  back with what was typed.
- **Slow spells are named in the log:** `store.slow`, `tmux.slow` and `runtime.lag` say who waited
  for whom. Every diagnostic log is rotated at a bounded size.

## Changed

- **Agents' notes are tasks.** An agent no longer keeps bookmarks and reminders for you
  (`add_notes_for_user` and its three companions are gone): what it notices goes to the board. What
  agents kept before stays with your bookmarks and reminders, and Convert to task makes one a task.
- **`terminum mcp` lists four tools:** `search_tools`, `get_tool_info`, `execute_tool` and
  `update_session_plan`; an agent finds every other tool by the action it needs and runs it through
  `execute_tool`. An agent started without permission prompts needs `execute_tool` allowed (Claude
  Code: `--allowedTools mcp__plugin_terminum_terminum__execute_tool`). A refused call names every
  fault of its arguments at once, and a tool's first refusal in a session carries its description.
- **A host's files and its agents' progress are set up by themselves** once the host attaches. Add
  host has no Files tick and `hosts add --files` is ignored. A host where agents' progress was
  turned off before this version gets it back once: turn it off again and it stays off. A coding
  agent installed on a host later gets terminum's hooks when terminum next starts or upgrades
  (`terminum hosts agents <host> on` at once); entries taken out by hand come back then, and
  `hosts agents <host> off` keeps them out.
- A project's session goes to its project's top when its agent takes a message, its rows gliding
  there.
- Every dialog has the size its use needs: one to type in or read takes 80% of the window it opens
  over, and its keys stay at its foot while its content scrolls. One Enter or Esc answers one
  dialog: a second one waits its turn.
- Fields have no line round them: a soft shade inside at rest, a glow in the focus color in focus.
- On a phone, a tablet or a narrow window, the lines of tasks and agents that need you fold into a
  red and a yellow counter. On an iPad the header has one key size on one line; the keyboard button
  is lit only while the on-screen keyboard is up, and with a hardware keyboard it and the hot keys
  button hide while you type.

## Fixed

- **A session whose agent ended its turn while a shell, monitor or task it started still runs**
  keeps its bar pulsing past 10 minutes, for as long as Claude Code's footer counts that work.
- **A window of your own tmux** (this Mac's or a host's) gets tmux's own size back when the last
  page showing it is hidden, even after another page sized it.
- A pane keeps the view's width when the quick shell closes just as its narrower size was being
  applied.
- One tmux server's hang or slow link no longer slows another server's list, screens or typing.
- A theme's link color too dark for a dark background, or too light for a light one, is made
  lighter or darker, its hue kept, until it reads (4.5:1), on the page and in View.
- The dashed drop outline stayed on the terminal after a drag ended without a drop.
- In Chrome an icon key pressed with the mouse kept a focus ring after Esc or a closed window; a
  row menu opened by a press gives the keys back to the terminal on Esc.

## A correction to v0.31.0's notes

They name "This pane has closed" under Fixed and Known. The failure was a test's own, found after
the release; terminum had no such fault.

## Known

A schedule its project's manager made tells its agent "set by a human", and a manager's run of a
schedule's task says "The human ran task … again": the words should name the manager.

## If you ran a build of `main` between the releases

- The store migrates by itself (schema 32): a task's `Bug:`, `Feat:`, `Debt:` or `Story:` moves
  from its title into its type, and messages get their tasks.
- A Run that was waiting for room is called off once with "The task's text changed": press Run
  again. A schedule's task left in TODO stays there until run or archived.
- Auto-Dispatch: a project that had it on keeps every severity and no wait; one that had turned
  itself off has its picking agent forgotten: choose it again.
- "waits for you" and "failed" lines closed before the upgrade show once more.
- The Dashboard's Active time changes its level on the day of the upgrade; an old `?days=` address
  opens the month. A manager's messages kept before the upgrade still say You.
