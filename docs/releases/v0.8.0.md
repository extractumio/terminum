# v0.8.0 — Agents' own hooks, sent history and reminders

## New

- **Claude Code and Codex tell terminum what they do.** `terminum hooks install` sets up the
  agents' own hooks: for Claude Code a plugin of terminum's (added with `claude plugin`, never
  by editing its settings), for Codex terminum's entries in `~/.codex/hooks.json` (backed up
  first, your entries kept; trust them once in Codex's `/hooks`). From then on a session's state
  (working, waiting for an approval or an answer, failed, done) comes from the agent itself,
  not only from its screen. The list says more too: the tool it runs and what it waits for
  ("Approve Bash: rm -rf", the question it asks) in the mark's tooltip and on the waiting card,
  why a turn failed, and how many subagents run. `terminum hooks` says what is set up;
  `terminum hooks remove` takes terminum's hooks out. `terminum status`, `open` and `install`
  say when an agent is found without them. Without hooks terminum reads screens as before.
- **Sent history.** Every prompt and command you send is kept per project (its host and
  folder) in `~/.terminum/sessions`. The speech bubble under the split shows the last one as
  Markdown; ↑ older, ↓ newer, Copy. An agent's prompt comes exactly from its hooks. A line you
  start with a space is not kept, and values of words named like secrets (`API_TOKEN=…`,
  `--password …`, `Bearer …`) and secret-shaped words are written as `[redacted]`.
- **Reminders.** A bookmark's dialog now has Bookmark | Reminder. A reminder comes up each time
  its session's agent ends a turn: a pale fuchsia bell blinks over whichever session you are in,
  until you press it. Its pane shows every open reminder as Markdown: Open goes to its text,
  Close puts it down until the next turn ends, Resolve ends it. A session with an open
  reminder has a fuchsia strip in the list.
- **Restore after a kill, not only a reboot.** If terminum's tmux is killed, your own attached
  tmux server is gone, or a host's tmux started anew, their sessions, windows and folders come
  back.

## Changed

- **The terminal's buttons in one column**: find, split and sent history, then, set apart, the
  colored ones (bookmarks and reminders) alike, without glow. Their panes open beside them.
  A split's terminal shows none of them, and waiting cards no longer cover them.
- The header's bar no longer pulses while an agent works; the list's still does.

## Fixed

- **"Sized for another screen" after a split** while a phone that had typed last lay locked:
  a hidden page now gives its window back to the page still looking at it, at once.
- **A Codex started without `--no-alt-screen`** (as `codex resume` is) runs on the alternate
  screen, where tmux keeps no scrollback. Scrolling up there now says so and how to fix it:
  `codex --no-alt-screen`, or `alternate_screen = "never"` under `[tui]` in
  `~/.codex/config.toml`.
- `terminum hook install` (a typo of `hooks`) no longer waits for keys; it names the command.

## Upgrading

`terminum upgrade`, then `terminum hooks install` to set up the agents' hooks (Codex asks you
to trust them in `/hooks`; Claude Code and Codex sessions started afterwards use them).
Nothing else to migrate.

## Validation

The following pass on the released tree:

- Rust unit tests and `cargo clippy` with no warnings; UI, page and script unit tests
  (`make test`).
- The protocol checks against a private terminumd and tmux server: core, access, restore,
  attach, the agents' states, and the new hooks check (real `terminum hook` runs: states,
  tools, approvals, failures, subagents, sent history, reminders up, closed and resolved, the
  hook's time: about 5 ms); remote hosts (stand-in ssh).
- The page's browser checks in Chromium and WebKit at a wide and a phone size, with new checks
  for the sent history and reminders; the Files panel's browser checks; the live checks.
- `terminum hooks install claude` and `remove` against the real Claude Code CLI in a temporary
  home; its `claude plugin validate` passes for the plugin and the marketplace.
- `scripts/security_check.sh`.

The sizing check's dragged-window case (`scripts/e2e_sizing.py`) fails most runs on this Mac,
with this release and with v0.7.0 alike: a timing check, not changed here.

Not checked: Codex loading terminum's `hooks.json` and running its events (the entries follow
the event names, `matcher`, `async` and `timeout` of Codex 0.163's own hooks); a live Claude
Code session's events through the plugin (the hook's posts are checked with real `terminum
hook` runs); an iPhone itself.
