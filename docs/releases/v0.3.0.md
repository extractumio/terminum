# v0.3.0 — scrolling keeps up over ssh

## Changed

- **Scrolling a full-screen program on a far host keeps up.** Scrolling the history of Codex
  (or any program that reads the mouse) in a session on a host lagged seconds behind a
  trackpad. Each wheel event used to cost one round trip to the host. Now:
  - the page sends the wheel at most once per frame, as text-line steps;
  - terminumd sends each burst to tmux in one command, in order with your keys.

  Through a stand-in ssh with 25 ms each way, the last of 120 wheel events used to be drawn
  5.8 s after you stopped scrolling. Now it is drawn in 0.1 s.

## Upgrading

`terminum upgrade`. Nothing to migrate.

## Validation

The following pass on the released tree:

- Rust unit tests and `cargo clippy` with no warnings; UI, page and script unit tests
  (`make test`).
- The protocol checks against a private terminumd and tmux server: core, access, restore,
  sizing, remote hosts, your own sessions here and on a host (stand-in ssh).
- The page's browser checks in Chromium and WebKit, at a wide and a phone size. The Files
  panel's browser checks, and the live checks against a private tmux server.
- `scripts/security_check.sh`, and the installer's check in a temporary home.

Not checked: a real sshd for remote hosts; scrolling with a real trackpad on a far host.
